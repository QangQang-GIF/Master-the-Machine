# CR (contract first, company standard exactly, evidence for every row)

Follow `mtm-init` and `mtm-worker`. Root owns Start Work, integration, push, and Submit.

1. **Commands**: tests/checks/seeds through `project_runtime.py ... run`, browser/HTTP captures through `project_runtime.py ... session` (syntax in `mtm-worker`). Use the commands the MVS, the brief or `env-require/README.md` state; never assume a package manager and never start servers by hand.
2. **Extract the contract first**: from `challenge/<key>.md`, the MVS file, the submit template/schema and any provided scripts, list the fixed names (module paths, exported functions and fields, handler names, routes, `data-testid`s, button labels, output file names such as `reconciliation-YYYY-MM.csv`) and use them verbatim.
3. **Company standard**: when the brief cites a KB standard or rule, fetch it with `call_company_tools` and implement every rule it states, including formats, rounding and edge cases; hidden checks are built from it. Add boundary tests for each rule.
4. **Prerequisites**: if the brief says the change must run on source that contains another item's fix, take it from the root branch once that item is submitted (`git rebase <assigned branch>`), never a merge commit.
5. **Official data and MVS**: use the official QA fixture in `answers/<key>/evidence/` (never synthetic data). Load it with a server-side test through the application's handlers first and take the summary fields and exported files from that run (see `mtm-worker` section 4); the UI is only for screenshots. Run provided seed/check scripts the way their header or the MVS says; copy a provided `challenge/<KEY>-mvs.test.ts` unchanged to the location the MVS states and write its log under the exact required name.
6. **UI and exports**: produce every required screenshot/CSV/HTTP evidence in one `session` pass that follows `env-require/README.md`, at the viewport the MVS states; exported files must be generated by the application, not written by hand.
7. **Hand-off**: each PASS row cites its required evidence; `status: "DONE"` when every MVS row is PASS, otherwise `PARTIAL` with honest `NOT_RUN`/`FAIL`. Run `metadata.submit_schema_check`, commit everything, then write `worker_result.json` with `status: "READY_FOR_REVIEW"`.
